# Quality Gate v5.0.0

Gate больше не запускает pytest и Coverage. Это относится к коммит-хуку, `check`, `check --profile`
и `audit`. Падающий тест сам по себе не блокирует коммит через Gate. Линтинг, форматирование,
проверка типов, зависимостей, безопасности и репозитория сохраняются. Успешный Gate подтверждает
только выполненные проверки качества кода.

Общий CI запускает полный pytest отдельной задачей для PR в основную ветку. Проверяется
предполагаемый результат слияния актуальных base и head. Обязательный результат `Quality Gate`
учитывает обе независимые задачи. Ошибка, отмена или неполная проверка тестов блокирует успех.
Обычный push или merge в main не добавляет ещё один полный pytest.

Релизная проверка сохраняет отдельный полный pytest из установленного артефакта на Windows
и Linux с привязкой к точному исходному коммиту. Сбой блокирует публикацию. `setup` продолжает
готовить pytest, а тестовые пути и runtime inventory сохраняют прежний формат.

Ручной `check --profile` показывает длительности проверок качества и ожидания локальной очереди.
Native-кэши Ruff и mypy разделяются по точному содержимому движка. Эти изменения не являются
измеренным ускорением: исключение тестовой работы из Gate меняет состав выполняемой проверки.

Для перехода после публикации обновите policy release и SHA общего workflow совместно.
В caller с явным списком событий PR добавьте `edited`, чтобы смена ветки назначения запускала
новую проверку. Агент запускает поведенческие тесты отдельно через существующий test-runner.
Уже опубликованные версии и пины потребителей этим PR не изменяются.
