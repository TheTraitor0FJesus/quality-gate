# Quality Gate 2.1.0

Добавлен общий механизм подготовки и публикации релизов для репозиториев-потребителей. Он проверяет релизное решение в PR, сохраняет исходный кандидат после слияния и публикует релиз после проверки происхождения и содержимого артефактов.

Повторный запуск проверяет уже завершённый релиз или дозагружает недостающие файлы совпадающего draft. Восстановление по номеру слитого PR сохраняет первоначальные исходники и разрешение публикации при обновлении инструментария. Общий интерфейс поддерживает доказательства для архивов, образов и пакетов.

Исправлено получение журналов GitHub Actions при публикации через GitHub CLI 2.100 и новее. При отказе CLI из-за управляющих последовательностей запрос журнала повторяется один раз с явным разрешением; HTTP-ошибки, тайм-ауты и другие отказы по-прежнему останавливают публикацию.

CLI, schema 2, контракт hook/runtime v2 и Windows/Linux ZIP сохраняют совместимость. Существующим потребителям адаптация не требуется. Подключение общего publisher и переход на новую версию Quality Gate выполняются явно: reusable workflows и helper выбираются по одной полной ревизии, принятой после публикации и проверки релиза. Автоматического обновления потребителей или развёртывания сервисов нет.

# Quality Gate 2.2.0

Изменение MINOR относительно v2.1.0: общий publisher получает доступ к GHCR через короткоживущий `GITHUB_TOKEN` вызывающего workflow. `RELEASE_TOKEN` используется только для GitHub Release API, а producer-job получает собственный `GITHUB_TOKEN` с `packages: write`. Для приватного GHCR-пакета в другом репозитории владелец пакета один раз выдаёт вызывающему репозиторию Read в **Manage Actions access**.

Проверка provenance связывает artifact с job из той же producer-попытки. Успешный повторно использованный job может подтвердить artifact предыдущей попытки только при совпадении API-записей обеих попыток. Publisher ограниченно повторяет запросы при неполных данных GitHub API и останавливает публикацию с диагностикой, если evidence отсутствует или не совпадает.

Quality Gate, parity и release-процессы используют отдельный временный каталог в корневом `temp/` проверяемого репозитория. При запуске удаляются оставшиеся неактивные каталоги, а временные каталоги кэша и атомарной замены остаются рядом со своими постоянными целями. Для read-only checkout и candidate snapshot используется закрытый хешированный per-repository workspace в пользовательском системном temp. Каждый consumer должен добавить `/temp/` в свой `.gitignore`.

Consumers обновляют Quality Gate и reusable-workflow revision только отдельным явным изменением после проверки опубликованного релиза. ARGUS_TG и ARGUS_tracker в этой версии не переключаются.

# Quality Gate 2.3.0

Изменение MINOR относительно v2.2.0: общий publisher публикует образы в GHCR через отдельный проверяемый writer. Writer сверяет исходную ревизию образа с одобренным исходным кодом, а publisher до изменения GitHub Release проверяет сохранённое подтверждение публикации и читает образ обратно по его неизменяемому digest. Для GHCR и GitHub Release используется автоматически выданный `GITHUB_TOKEN`; отдельный `RELEASE_TOKEN` или GHCR PAT не нужен. Job publisher получает только `contents: write`, а отдельный вызов writer — только `packages: write`. Для приватного пакета в другом репозитории владелец один раз настраивает доступ вызывающего репозитория в **Manage Actions access**.

# Quality Gate 2.4.0

Добавлено узкое исключение политики для автоматического запроса ревью владельца на Dependabot PR. Quality Gate разрешает job-scoped `pull-requests: write` только для точного утверждённого шаблона `.github/workflows/dependabot-review.yml`: `pull_request_target` для недрафтовых PR бота в `main`, выбор владельца репозитория, защита от повторного запроса и ограниченное время выполнения. Изменение пути, триггера, guards, прав, окружения, команд или шагов закрывает исключение. Checkout PR и выполнение кода продукта в этом шаблоне не разрешаются.

Это новая обратно совместимая возможность, MINOR относительно v2.3.0. CLI, schema 2, hook/runtime v2 и Windows/Linux ZIP сохраняют совместимость. Существующим потребителям адаптация не требуется. Для подключения reviewer workflow нужно явно обновить опубликованную policy/helper-пару; сам workflow включается отдельным изменением после проверки релиза. Публикация не обновляет потребителей автоматически и не развёртывает сервисы.

# Quality Gate 2.4.1

Исправлено определение отсутствующего точного GHCR version-tag на этапе общей публикации. Writer продолжает работу только при явном полном ответе об отсутствующем manifest именно этого тега и без сохранённого receipt digest; прочие ошибки доступа к Docker/GHCR остаются отказами.

# Quality Gate 2.4.2

Уточнена предварительная проверка GHCR: writer распознаёт подтверждённое отсутствие точного version-tag, включая ответ Docker `not found`, только для ожидаемого тега без сохранённого receipt digest. Сообщения о сбоях Docker теперь называют разрешённую подкоманду без вывода ссылок на образы, аргументов, путей или секретов. Ошибки других тегов, доступа и сети по-прежнему останавливают публикацию.
